## Decisions

1. Use an instance-local controller over the existing `ws` transport and Node HMAC. BK/BS already configure an HMAC Spot account; adding RSA/Ed25519 credential setup is not part of this migration. The public-market SDK remains unchanged. The installed SDK's WebSocket layer auto-reconnects and strips subscriptionId before delivery; using it would leave two lifecycle owners or require patching SDK internals.
2. The controller exposes start, stop and status; callbacks publish accepted events and health. It registers listeners before sending the signed subscription, accepts only the matching request acknowledgement, supports subscriptionId zero, and dispatches only the current subscription's envelope. No event queue can grow while awaiting acknowledgement: pre-ack events are ignored and REST catch-up follows acknowledgement.
3. Connection and subscription each admit weight 2 through the existing limiter. The generation is checked inside each admitted operation, so teardown cannot create a late socket or signed request. Sign at send time. Never log raw signed frames, credentials, untrusted close reasons or raw parse failures.
4. Bound handshake/subscription to 10 seconds, message payload to 256 KiB, and retries to five delays (3/6/9/12/15 seconds). Observe server ping/pong traffic so a quiet account is healthy; terminate a connection with no peer traffic for 60 seconds. Re-subscribe on server shutdown, stream termination or unexpected close. Authentication and rate-limit refusal stop automatic retry; reactivation can retry after the operator corrects the cause.
5. Main owns one controller across Spot renderers. The last Spot consumer or main shutdown stops it synchronously, including queued retries. Public ticker and Futures lifecycle stay separate. A new renderer gets the current status even without a transition. Reconnection triggers account catch-up (balances and open orders); a stream acknowledgement is not labeled as a completed REST account snapshot.
6. Refuse new Spot placement while subscription is not ready, with a dedicated visible reason; never block cancel/refresh or replay any trade as part of recovery. Renderer health is session-local and resets on gateway loss or market deactivation. A persistent banner describes unavailable private updates and the placement restriction.
7. Retain health in GatewayProvider, keyed by connection and activation generation: an acknowledgement and health may arrive before workspace listeners mount. Every accepted private event and health transition invalidates the existing per-renderer account-read epoch. The shared balance fallback also checks a private revision before reading and publishing, coalescing a trailing read when an in-flight snapshot is superseded; no result is broadcast after the last Spot consumer leaves.

## Impact and risk

GitNexus before edits: startUserDataStream HIGH, stopSharedSpotConnections CRITICAL, both disclosed before implementation. Direct owners include initializeSpotData, deactivateSpotData, setupBinanceConnection and close. Shared close-name graph edges also reach Futures; source review must verify those owners explicitly. Zero callers for legacy adapter methods and React callbacks were supplemented by actual imports/calls. Use full lifecycle/service/UI tests and uncapped exact-path graph review, not the old CLI's bounded changed-file list alone.

## Verification and migration

Write production first. Replace tests that prescribe retired listenKey traffic with tests proving the same ownership guarantees on the new protocol. Test HMAC with a local WebSocket server, subscriptionId zero, wrong ack/id, late frames, timeout, quiet-account heartbeat, close/reconnect, exhausted/auth failure, stop during admission and reactivation. Prove main fan-out, balance/open-order catch-up, placement refusal and cancel availability, plus renderer warning/reset. Run full checks before commit; operator live confirmation is still required before archive. No actual trading is authorized for these tests.
